# Running bridge LAN-only configuration, 2026-10-10

## Applied change

The running DietPi bridge's `/etc/eufy-wall-bridge.yaml` lacked a `lan` section.
At 17:15:50 UTC it was atomically updated to:

```yaml
lan:
  cidr: 192.168.23.0/24
  force: true
```

The original file was backed up alongside it with suffix
`.before-force-lan-2026-10-10T17-15-50-963Z`. The existing YAML parser preserved
the other configuration, and the deployed `loadConfig` validated the temporary
file using the running service's environment before replacement. File ownership
and permissions were preserved. Only the application service was restarted;
host networking was not changed.

The existing SDK peer callback enforces the configured CIDR before control/media
peer selection. The existing bridge guard also checks connected sessions.
Startup recorded `lan.force=true (P2P-only)` and selected two LAN control peers:
the HomeBase serving two cameras and the independent camera. Cloud login and
lookup remain available. Installer updates preserve this configuration file.

## Live verification

- `/healthz` reported authenticated/healthy, three active streams, no blocked
  cameras, zero stalls after restart, and go2rtc running.
- A passive Ethernet capture from approximately 17:16:19.702 through
  17:16:49.727 UTC observed incoming UDP P2P DATA (`f1d0`) addressed to socket
  ports owned by the bridge process. Port ownership was refreshed every second.
  It recorded **12,636 data packets from two peers inside the configured CIDR**
  and **zero data packets from outside it**. Cloud lookup traffic was excluded
  by message type. This is a bounded observation, not a claim that the bridge
  never communicates with internet services.
- Both Fire TVs automatically reconnected. Between 17:16:34 and 17:16:47 UTC,
  Garage rendered-frame counts increased from 415 to 565 on each TV. Front Door
  counts increased from 463 to 615 on one and 465 to 616 on the other. Both used
  the Amlogic hardware AVC decoder and reported zero queued compressed units.

This verifies the deployed connection policy and playback recovery. It does not
establish a fix for the separate source pauses or missing camera timestamp.
No SDK, decoder, resolution, or buffer setting was changed for this deployment.
